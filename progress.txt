==============================================================================
A. PROJECT OVERVIEW
==============================================================================

Teknologi dan arsitektur aktual:
- Python 3.14.7 di lingkungan pengembangan Windows.
- Aplikasi desktop offline, satu PC, tanpa server/internet/cloud.
- UI: CustomTkinter 5.2.2 (Tkinter).
- Database: SQLite melalui modul standar `sqlite3`.
- PDF: reportlab 4.2.5.
- Password: bcrypt 4.2.0.
- Packaging: PyInstaller (requirements-dev.txt), mode "onedir" melalui
  `build.spec` dan `build.bat`.

Entry point dan modul utama:
- `app.py`: entry point; single-instance lock, pemulihan restore terputus,
  inisialisasi database, alur login -> main window -> logout.
- `database/database.py`: koneksi, transaksi, deteksi versi, migrasi
  v1 -> v2 -> v3 -> v4, validasi schema, backup migrasi.
- `database/schema.sql`: definisi tabel.
- `database/integrity.py`: pemeriksaan read-only (header, integrity_check,
  foreign_key_check, tabel/kolom, hitungan, digest isi).
- `models/`: user, customer, product, debt, payment, purchase, sale,
  history, report, settings, supplier.
- `views/`: login, main_window, dashboard, customers, products, debts,
  payments, purchases, sales, history, reports, settings.
- `components/`: dialog, form, tabel, kartu, badge, detail dialog.
- `utils/`: backup, printer, security, formatter, barcode, theme,
  error_handler, instance_lock.

Lokasi database dan mekanisme penyimpanan:
- `data/warung.db` relatif terhadap folder aplikasi.
- `get_database_path()` membuat folder `data/` bila belum ada.
- Saat frozen (PyInstaller), folder dasar adalah folder EXE, bukan
  folder `_internal`.
- Database aktif saat audit: schema v4, `integrity_check=ok`,
  `foreign_key_check=0`, ukuran 208.896 byte, `journal_mode=delete`.
- Tidak ada perubahan schema, lokasi database, atau nama EXE yang
  diizinkan tanpa keputusan eksplisit.

Sistem backup/restore:
- Backup memakai SQLite Backup API, lalu divalidasi (integritas, FK,
  schema, jumlah/total data, digest isi) sebelum dianggap berhasil.
- Restore memakai staging di `data/.restore_work/`, migrasi hanya pada
  salinan staging, safety backup terverifikasi, swap atomik, verifikasi
  pasca-restore, rollback bila gagal.
- Marker `data/.restore_state.json` dipakai untuk pemulihan otomatis
  saat startup bila restore terputus.
- Safety backup `data/backup/before_restore_*.db` dan backup lama tidak
  dihapus otomatis.
- Hanya satu instance aplikasi yang diizinkan (`data/.warung.lock`).

Sistem pengujian dan packaging EXE:
- `python -m pytest -q`: 175 test otomatis (per 2026-11-26), tanpa
  warning.
- `python tests/test_integration.py`: skrip end-to-end manual; sengaja
  tidak dikoleksi pytest karena seluruh alur berjalan saat diimpor.
- `tests/test_customer_history_pdf.py`: test khusus data `items` dan
  isi PDF `customer_history` (memeriksa teks flowable, bukan parsing
  PDF terkompresi).
- `build.spec` + `build.bat` tersedia; folder `build/` dan `dist/` ada,
  tetapi smoke test EXE hasil build belum diverifikasi ulang pada sesi
  ini.
